## 3. 首版目标

### 用户目标

- 访客能够理解 initlife 的定位和各产品的差异。
- 访客能够方便地找到产品获取、支持和隐私信息。
- 搜索引擎和社交分享能够正确识别公开内容。
- 手机、平板和桌面浏览均具备完整可用性。

### 业务目标

- 建立 `initlife.com` 的统一品牌入口。
- 减少各产品重复维护品牌、支持与法律基础信息的成本。
- 保持内容和工程结构可维护，为后续扩展保留空间。

### 非目标

- 账号、支付、社区、内容管理后台。
- 博客或高频动态系统。
- 未正式支持平台的功能承诺。
- 未经确认的数据分析、广告或第三方追踪。

## 4. 当前阶段的工程约束

- 公开内容中的产品功能、平台、隐私和安全表述必须有可核验来源。
- 联系邮箱统一使用 `initlifeltd@gmail.com`。
- GitHub 仓库和公开网站均视为公开环境，仓库历史也不能作为秘密存储位置。
- 禁止提交密码、API Key、访问令牌、Cookie、证书、私钥、签名文件、未脱敏用户数据、个人隐私或内部账号信息。
- 后续如确需配置秘密，应使用本地忽略文件或 GitHub Actions Secrets，并只在仓库中保留无敏感值的示例文件。
- 在开始开发时建立 `.gitignore`、环境变量示例和提交前敏感信息检查。

## 5. 推荐里程碑

### M0：输入确认与工程基线

- 确认开始开发所需的输入和实施选择。
- 初始化 Git、关联远端仓库并建立基本的质量与敏感信息检查。
- 补齐三款产品的内容资料表。

完成标准：本地可运行空壳站点，路由和内容模型确定，关键待办均有责任归属。

### M1：公开内容与基础体验

- 实现已确认的公开内容与基础交互。
- 完成移动端与桌面端适配。
- 建立 SEO、无障碍和图片规范。

完成标准：已确认内容完整、响应式可用，并通过基础性能与无障碍检查。

### M2：产品资料落地

- 落地 SecretBank、嘟惠修、SecretBankX 的已确认资料。
- 接入准确的商店链接、平台版本、截图和支持信息。
- 复用并核验 SecretBankX 现有内容。

完成标准：每款产品都能形成“理解—信任—下载/支持”的完整路径。

### M3：支持与法律信息

- 落地已确认的支持、隐私及其他必要法律信息。
- 校验全站链接、日期、邮箱和法律文本。

完成标准：所有页可从导航或页脚访问，法律内容完成业务确认。

### M4：上线准备

- 完成跨设备和主流浏览器检查。
- 完成 Lighthouse、链接、元信息、sitemap 和分享卡片检查。
- 配置阿里云 Web 服务、`initlife.com`、HTTPS 和回滚说明。

完成标准：生产域名可访问，关键路径无阻断问题，部署可重复执行。

## 7. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 产品资料不完整或相互矛盾 | 页面无法定稿、返工 | 使用统一内容清单，指定每款产品的事实来源和确认人 |
| 安全与隐私表述未经核验 | 信任与合规风险 | 所有加密、同步、数据收集声明由产品代码或正式政策佐证 |
| 部署与域名决策滞后 | 做完无法上线 | 在 M0 确定托管、DNS 权限与回滚方案 |
| 敏感信息进入公开仓库或站点 | 凭证泄露、隐私与安全事件 | 默认公开原则、`.gitignore`、Secrets、提交前扫描和历史检查 |
